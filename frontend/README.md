# PileScan frontend

Mobile-first installable PWA: photograph a pile of loose bricks, review and correct the detected
pieces, then see the official sets the pile most likely comes from.

Angular 22 (standalone components, signals, zoneless, strict TypeScript) · Ionic 9 · Capacitor 8
Camera · `@angular/service-worker` · Vitest.

## Run

Angular 22 needs **Node >= 22.22.3 or >= 24.15** (`engines` in `package.json`).

```bash
npm ci
npm start               # http://localhost:4200, /api proxied to http://localhost:8080 (proxy.conf.json)
npm test                # unit tests (Vitest, one run)
npm run build           # production build in dist/pilescan/browser (includes the service worker)
npm run generate:api    # regenerate the API client from ../docs/api/openapi.yaml
npm run check:api       # fails if the committed client is out of sync with the spec
```

Docker (also started by `docker compose up` from the repo root, on http://localhost:4200):

```bash
docker build -t pilescan-frontend .
docker run --rm -p 4200:80 pilescan-frontend   # nginx serves the build, /api/* -> backend:8080
```

The service worker is only enabled in production builds, so test installability with the Docker
image or `npm run build` plus a static server, not with `ng serve`.

## Structure

```
src/app/
  core/
    api/generated/       typed client generated by ng-openapi-gen (committed, do not edit)
    scan.store.ts        signal store for the scan under review (upload, load, update, add, remove)
    catalog.service.ts   colors (cached) and part search
    scan-photo.service.ts  loads the scan image once; shared by canvas and crop thumbnails
    api-error.ts         HttpErrorResponse (problem+json) -> user-facing message
  features/
    capture/             photo source, tips, upload + loading overlay
    review/              canvas with boxes, grouped list, edit/add dialog
    results/             ranked set cards with expandable missing parts
  shared/
    bbox-geometry.ts     image/canvas/CSS coordinate conversion, hit testing, box drawing
    confidence.ts        confidence -> level/color/label
    grouping.ts          summary rebuilding from detections, labels, text contrast
    image-prep.ts        file validation and downscaling of oversized photos
    ui/                  footer (credits + disclaimer), color swatch
```

Routes: `/` capture, `/scan/:id` review, `/scan/:id/results` results (all lazy loaded).

## Decisions

- **Generated client, ng-openapi-gen.** Runs on Node only (no Java), emits plain functions plus
  an `Api.invoke()` helper, and every HTTP call goes through it, so no endpoint URL is written by
  hand. The output is committed because the Docker build context is `./frontend` only;
  `npm run check:api` guards against drift. The root URL is `''` (same origin): nginx in Docker,
  `proxy.conf.json` in dev.
- **Signals, no NgRx.** One small `ScanStore` holds the scan. The grouped summary is *derived*
  from the detections (`buildSummary`, same rules as the backend), so every edit updates the UI
  without refetching. Deletes are optimistic with rollback.
- **Pure helpers for the risky logic.** Bounding boxes are in image pixels, the canvas has its own
  internal size, and CSS scales it again. All conversions live in `bbox-geometry.ts` and are unit
  tested without a DOM.
- **Canvas, not overlay divs.** The photo and boxes are painted on one canvas so crop thumbnails
  and drawing share the same pixel space. Taps resolve to the smallest box under the pointer.
  Since a canvas is opaque to assistive tech, every piece is also reachable from the list below it.
- **Native `<dialog>` for the edit sheet.** Focus trapping, Escape and modal semantics come from
  the platform instead of an Ionic overlay.
- **Camera.** In a native Capacitor shell the Camera plugin is used. In a browser a file input
  with `capture="environment"` opens the camera app on phones, and a second input picks from the
  gallery or, on desktop, from disk. No native projects are generated in this repo.
- **Large photos** (> 12 MB) are re-encoded client-side to JPEG (max edge 3000 px) to stay under
  the API's 15 MB limit.
- **Accessibility.** Confidence is always also written as text, colors always carry their name,
  buttons are at least 44 px, focus rings are visible, `prefers-reduced-motion` is respected.
- **Service worker** excludes `/api/**` from navigation handling (the scan image URL has no file
  extension and would otherwise be answered with `index.html`). API responses are not cached.
- Thumbnails use the catalog `imageUrl` first and fall back to a crop of the user's photo.
- No LEGO name or logo in the UI, apart from the trademark disclaimer in the footer.

## Known limits

- The set results screen asks for the top 5 only (`limit=5`).
- Editing a piece changes that one detection; there is no "apply to all pieces in this group".
- Native Android/iOS shells are not generated here; the Camera plugin path is wired but untested
  on a device.
